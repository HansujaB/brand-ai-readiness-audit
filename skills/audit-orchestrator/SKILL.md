Use this entrypoint for a complete audit. Read the three specialist SKILL.md files for their decision procedures and [the report contract](references/schema.md). Compose their checks once through the shared runner.

1. Start one five-minute deadline for collection, review and final validation. Establish one country/language from the request, URL or published website metadata; never silently assume India. Follow only the supplied URL's exact origin (scheme, hostname and effective port), including assets, robots.txt and redirects. Do not fetch news or outside publishers.
2. Run `python skills/audit-orchestrator/scripts/run_audit.py URL --budget 210` from the marketplace root, adding `--country` and `--language` when provided. It writes one `<company>_report.json`, such as `ikea_report.json` or `lifestyle_report.json`. Pass `--brand` when the company name is supplied; otherwise use the published site name or domain fallback. The runner prints the final filename. Every run uses the full workflow: up to nine initial pages, three information follow-ups and three representative browser pages within the budget. Use `--pages` for relevant same-locale URLs when needed.
3. Review the proposed findings for the actual business decisions: offering, price/commitment, suitability, conditions and the next public information step. Keep detailed checks, source spans and unresolved questions internal; the Python `audit()` result can be reviewed in memory. Do not write diagnostics, evidence dumps, screenshots, alternate reports or new fact-manifest files.
4. Resolve only high-impact uncertainty that fits the remaining deadline. Reuse collected evidence first. Check that compared prices refer to the product rather than coupon discounts, and that policy durations describe the same event and conditions. Use a targeted same-origin source only if time remains for final validation. Do not restart a broad crawl or continue review beyond five minutes.
5. Write for a business owner: one clear title, severity, a short evidence sentence and a specific action per distinct problem. Give the action two or three concise sentences describing what to change and where, plus one `verification` sentence explaining how to check success. Apply the same level of detail to improvements; avoid generic filler or long technical instructions. Retain affected-page links when useful. Merge repetitions requiring the same fix; preserve distinct causes and entities. Keep the required fields from the competition example and add a separate `improvements_summary` counting the listed improvements by priority. Optionally include up to three supported improvements and one short note for an important assessment limitation. Do not add coverage objects, confidence fields, request counts, test results, review queues or raw technical data. No invented findings or guaranteed ranking claims.
6. Validate and recount both summaries using the filename printed by the runner, for example `python skills/audit-orchestrator/scripts/validate_report.py lifestyle_report.json --write`. Update that same file after review and deliver only it. Source collection, evidence review and validation share the original deadline; an incomplete run gets a brief note, not extra report files.

All collection remains anonymous, read-only and robots-respecting. No authenticated pages, forms that change state, cart/checkout operations or private destinations. Tool failures are assessment limitations, never website defects. Keep detailed technical measurements inside the audit; the owner's action and verification should explain what to change and how to check the outcome in plain language.
